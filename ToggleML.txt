Goal

Add a global “Model On/Off” switch that lets an operator stop the ML engine from reading any live metrics (the dashboard will still display raw Prometheus charts, but no anomaly scores, risk predictions, or alerts will be generated).

Below is a complete, low‑impact implementation plan that:

Exposes a REST endpoint (/api/model/enable) to toggle the engine at runtime.
Persists the flag in the existing SQLite DB (so the setting survives container restarts).
Modifies ModelEngine to short‑circuit when the flag is False.
Adds a UI toggle on the Settings page (or a new “Model Control” card on the AI & Predictions page).

All changes are confined to the existing code‑base – no new services or external hosts are required.

1️⃣ Backend changes
1.1 DB table for the flag

backend/app/database.py already contains helper functions for a tiny SQLite DB (app.db).
Add a new table with a single row that stores the boolean flag.

python
# backend/app/database.py
def init_app_db() -> None:
    """Called on startup – create tables if missing."""
    conn = sqlite3.connect(DB_PATH)
    cur = conn.cursor()
    # Existing tables …
    cur.execute(
        """
        CREATE TABLE IF NOT EXISTS ml_engine_settings (
            id INTEGER PRIMARY KEY CHECK (id = 1),
            enabled INTEGER NOT NULL CHECK (enabled IN (0,1))
        )
        """
    )
    # Ensure a single row exists (default: enabled)
    cur.execute("INSERT OR IGNORE INTO ml_engine_settings (id, enabled) VALUES (1, 1)")
    conn.commit()
    conn.close()

Add two tiny helpers:

python
# backend/app/database.py
def get_ml_engine_enabled() -> bool:
    conn = sqlite3.connect(DB_PATH)
    cur = conn.cursor()
    cur.execute("SELECT enabled FROM ml_engine_settings WHERE id = 1")
    row = cur.fetchone()
    conn.close()
    return bool(row[0]) if row else True   # default to enabled
def set_ml_engine_enabled(enabled: bool) -> None:
    conn = sqlite3.connect(DB_PATH)
    cur = conn.cursor()
    cur.execute(
        "UPDATE ml_engine_settings SET enabled = ? WHERE id = 1",
        (1 if enabled else 0,),
    )
    conn.commit()
    conn.close()

Why a DB row?
Persisted across container restarts and easy to query from any process. You could also use a JSON file, but the DB is already in the project.

1.2 API router for toggling

Create a new router file backend/app/api/model_control.py.

python
# backend/app/api/model_control.py
from fastapi import APIRouter, HTTPException
from pydantic import BaseModel
from ..database import get_ml_engine_enabled, set_ml_engine_enabled
router = APIRouter(prefix="/api/model", tags=["model-control"])
class ModelToggle(BaseModel):
    enabled: bool
@router.get("/enabled", response_model=bool)
def read_enabled() -> bool:
    """Current on/off state of the ML engine."""
    return get_ml_engine_enabled()
@router.post("/enabled")
def set_enabled(payload: ModelToggle) -> dict:
    """Enable or disable the whole ML pipeline."""
    set_ml_engine_enabled(payload.enabled)
    return {"enabled": payload.enabled}

1.3 Wire the flag into ModelEngine

Edit backend/app/ml_engine.py – add a short‑circuit at the top of score_node.

python
# backend/app/ml_engine.py
from .database import get_ml_engine_enabled
class ModelEngine:
    # existing __init__ …
    def score_node(self, feats: Dict[str, Any]) -> Dict[str, Any]:
        """Return a full prediction dict – or a placeholder when the engine is disabled."""
        # ------------- NEW: check global enable flag -------------
        if not get_ml_engine_enabled():
            # Return a safe “disabled” payload – risk = 0, no alerts, status = "DISABLED"
            node_id = str(feats.get("node_id", "unknown"))
            return {
                "failure_prob_1h": 0.0,
                "failure_prob_6h": 0.0,
                "failure_prob_24h": 0.0,
                "prediction_confidence": None,
                "prediction_source": "engine_disabled",
                "anomaly_score": 0.0,
                "consensus_count": 0,
                "consensus_votes": {
                    "isolation_forest": False,
                    "one_class_svm": False,
                    "lof": False,
                    "kmeans": False,
                },
                "node_health_score": 100.0,
                "health_classification": "Excellent",
                "fault_class": "normal",
                "fault_label": "Model disabled – no risk",
                "playbook_cmd": "",
                "playbook_advice": "The ML engine is currently turned off.",
                "top_features": [],
                "node_id": node_id,
            }
        # ---------------------------------------------------------
        # ... rest of the original scoring logic unchanged ...

Effect: When the flag is False, the backend still runs the Prometheus scrape, the RollingFeaturePipeline still builds enriched snapshots, but ModelEngine never runs any detector or supervised model – it simply returns a neutral payload. SmartAlertEngine will see failure_prob_1h == 0 and will not fire any alerts.

2️⃣ Front‑end changes
2.1 New React component – ModelToggleCard

Create frontend/src/components/ModelToggleCard.jsx (you can place it inside SettingsPage.jsx or the AI & Predictions page.)

jsx
import React, { useEffect, useState } from "react";
import Switch from "@headlessui/react"; // or any UI switch component you already use
import { fetchJson, postJson } from "../utils/api"; // tiny wrappers around fetch
export default function ModelToggleCard() {
  const [enabled, setEnabled] = useState(true);
  const [loading, setLoading] = useState(true);
  // Load current flag on mount
  useEffect(() => {
    fetchJson("/api/model/enabled")
      .then((data) => setEnabled(data))
      .finally(() => setLoading(false));
  }, []);
  const toggle = async (newVal) => {
    setEnabled(newVal);
    await postJson("/api/model/enabled", { enabled: newVal });
  };
  return (
    <div className="card p-4 shadow-md">
      <h3 className="text-lg font-semibold mb-2">ML Engine</h3>
      <p className="text-sm mb-3">
        Turn the whole predictive model on or off. When off, the dashboard will
        still display raw metrics but no risk scores, anomaly alerts, or
        playbooks are produced.
      </p>
      <div className="flex items-center">
        <span className="mr-2">{enabled ? "Enabled" : "Disabled"}</span>
        <button
          disabled={loading}
          className={`${
            enabled
              ? "bg-green-600"
              : "bg-gray-400"
          } relative inline-flex h-6 w-11 items-center rounded-full transition-colors focus:outline-none`}
          onClick={() => toggle(!enabled)}
        >
          <span
            className={`${
              enabled ? "translate-x-6" : "translate-x-1"
            } inline-block h-4 w-4 transform rounded-full bg-white transition-transform`}
          />
        </button>
      </div>
    </div>
  );
}

3️⃣ Persistence & Restart safety
The flag lives in SQLite (app.db).
On container start, backend/app/database.init_app_db() (called from main.py startup event) creates the table and populates the default enabled = 1.
Changing the flag via the UI updates the DB instantly; the backend reads it on every request (no caching), so the change takes effect the very next metric‑scoring cycle (≈ 5 seconds).

If you prefer a runtime‑only toggle (no DB write), simply replace the DB calls with an in‑memory global ENABLED = True variable. The DB approach is more robust for production.

5️⃣ How it behaves in production
Action	UI	API call	Backend effect
Disable	Click the toggle → “Disabled”	POST /api/model/enabled { "enabled": false }	set_ml_engine_enabled(False) writes DB; next scoring loop returns the neutral disabled payload; SmartAlertEngine never raises alerts.
Enable	Click the toggle → “Enabled”	POST /api/model/enabled { "enabled": true }	Flag restored; scoring resumes with unsupervised & supervised models.
Restart	Toggle state is persisted in SQLite, so after a container pod restart the flag is read again (GET /api/model/enabled).	–	No extra steps needed.

If you ever need per‑model granularity (e.g., turn off only the supervised predictor), you can extend the DB schema with extra columns (unsupervised_enabled, supervised_enabled) and add corresponding checks in ModelEngine.score_node. The same API pattern scales effortlessly.

TL;DR
Add a tiny DB table (ml_engine_settings) to store a boolean enabled flag.
Expose /api/model/enabled (GET/POST) to read and write that flag.
Guard ModelEngine.score_node – return a neutral payload when enabled is false.
Add a React switch on the Settings (or AI & Predictions) page that calls the endpoint.
The flag is persisted, survives restarts, and instantly stops/starts all ML‑derived risk scores and alerts.
